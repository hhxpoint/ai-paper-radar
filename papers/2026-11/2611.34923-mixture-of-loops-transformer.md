# Mixture-of-Loops Transformer

> **arXiv**：[2611.34923](https://arxiv.org/abs/2611.34923) · **主题**：`效率、系统与安全` · **发表**：2026-11-25
> **作者**：Lianghui Zhu、Shijie Wang、Xinggang Wang、Jinze Bai、Bo Wang、Xiang Bai · [PDF](https://arxiv.org/pdf/2611.34923) · [HTML](https://arxiv.org/html/2611.34923) · [代码](https://github.com/hustvl/MoLT) · [HF 讨论](https://huggingface.co/papers/2611.34923)  
> 状态：每日精读（智能体）

## 一句话结论
把循环之间传递的东西从残差流换成 KV 记忆：MoLA 让每层同时读当前 loop 的局部 KV 与上一 loop 的记忆 KV，MoLT-KV 再用 embedding 重启加严格前缀记忆消掉同位置跨 loop 依赖，从而能做单次遍历的 MoL 解码。400B token 预训练下 U-MoLT 在 700M 上以 1.7× token 效率追上 OLMo3 的平均验证 CE，3B MoE 上十域困惑度降 0.75、十任务准确率升 2.1 个点；S 尺寸（约 113M）延迟 996.6 ms 对 OLMo3 的 1000.6 ms。

## 为什么值得读（观点）
主流 looped Transformer 默认跨 loop 只有残差流一条通道，作者指出这同时是表达力与效率的瓶颈：反复把计算压进一条残差流会稀释信息，而每个 token 依赖自己上一 loop 的输出又逼着推理串行跑完所有 loop。把通道换成可寻址的 KV 记忆，是架构层面（而不是训练或推理技巧）的改动，并且诚实暴露了一个取舍——质量最好的配置恰好不能用单次遍历解码。

## 问题与动机
循环复用参数能在不增加参数量的前提下提升表达力，代价是推理成本随 loop 数线性增长。标准做法 loop residual 把每个 loop 的输出直接喂给下一个 loop：一方面表示在层与层、loop 与 loop 之间被反复压缩而退化，另一方面同位置跨 loop 依赖使模型无法并行或跳过 loop。

## 方法与关键洞察
MoLA 把 sequence KV 与 depth/loop KV 放进同一个 attention 分布。三种形态对应两种反馈：MoLT-R 保留残差流、额外读当前 loop 与上一 loop 在同位置的局部 KV，表达力优先；MoLT-KV 让每个 loop 从 embedding 重启，只读上一 loop 在 j<t 的严格前缀 memory KV 加当前 loop 的 local KV，配合 loop forcing（每个 loop 都从上一 loop 的记忆并行监督）训练，于是新 token 可以跳过前面所有 loop 只走一遍共享栈——这就是 MoL 解码，还能靠缓存前缀记忆外推到训练 loop 数之外。U-MoLT 再把记忆构建与预测读出分开：6 层 loop-KV encoder 加 6 层 cross-only decoder，decoder 用独立的 per-layer KV 投影读 encoder 归一化输出，因此可以跳过中间 loop 与非末尾 prompt 位置的 decoder 遍历而不改变预测。

## 证据与实验
400B token 从头预训练对比 OLMo3：700M dense 上 U-MoLT 十任务准确率 +2.5 点（MoLT-R +2.6），并以 1.7× token 效率追平 OLMo3 最终平均验证 CE；3B MoE（660M 激活）十域困惑度 −0.75、十任务 +2.1 点；Qwen3.5-0.8B-Base 上 100B token 继续预训练，11 个域 CE 全部低于匹配基线，平均 1.4× token 效率。延迟：S 尺寸（约 113M）、4096 token prefill 加 64 步解码，U-MoLT 配 MoL-Hybrid-2 为 996.6 ms，OLMo3 单 loop 为 1000.6 ms，固定 2-loop OLMo3 为 1974.3 ms。组件消融（S 尺寸、3B token、32 个配置）：2-loop 把 CE 从 3.318 降到 3.299，MoLT-R 加深度 KV 到 3.284，U-MoLT 最好 3.273（dense cross-loop re-proj，多 1.771M 参数、1001 ms/update），sparse 版 3.276、968 ms。

## 可质疑之处
① 组件消融的绝对增益很小：CE 3.318→3.273 只有 1.4%，而 headline 是 1.7× token 效率；且只有 seed 11、3B token，缺方差，3.273 与 3.276 这类差异无法判断显著。② 质量最优与效率最优不是同一个模型：论文明确 cross-loop 变体只能在当前 loop 单次解码、只有 current-loop 变体支持 MoL，所以 996.6 ms 对应的配置不是表里 CE 最低的那个，读者容易把两条 headline 拼成一个模型。③ 与 OLMo3 比的是同 token 预算而不是同 FLOPs 或同墙钟：2-loop 的 update time 从 494 ms 翻到约 942–1001 ms，1.7× token 效率只有在算力不变时才有意义，论文没给等 FLOPs 对照。④ MoLT-KV 的增益有相当部分来自深度 KV 而不是跨 loop KV：无 depth 的配置甚至比 2-loop baseline 差，而加上 own KV 就吃到主要改善。⑤ loop forcing 加 MoL 的「超出训练 loop 数」结论只在 S 尺寸消融，长序列与更多 loop 下的漂移未测。

## 与我的研究关联
对做 TTS/ASR 基座：单次遍历解码直接降解码延迟，对流式合成与长上下文识别有吸引力；「把中间计算当可寻址记忆而不是残差流」也可迁到多模态编码器的跨层复用。对智能体：多步工具调用里每一步读上一步的 KV 前缀、而不重跑整条链，是同构的省算力做法。RL 方向关联较弱。

## 延伸阅读
Universal Transformer / ALBERT 的权重共享；OLMo3 是主基线；YOCO、Universal YOCO 与 DeepSeek CED 的 encoder-source 复用；MoDA（Mixture-of-Depths Attention）、DenseFormer、Attention Residuals 的跨深度注意力；Transformer-XL、Feedback Transformer、LCKV 的前缀记忆；LPT、PLT、LoopFold 的 looped 解码加速。

## 摘要原文

<summary>展开英文摘要</summary>

Looped Transformers boost expressivity by reusing shared layers across loops, yet at the cost of efficiency. Pushing their expressivity-efficiency frontier requires rethinking the core mechanism connecting adjacent loops: What should be passed as a Transformer loops? We introduce Mixture-of-Loops Transformer (MoLT), whose Mixture-of-Loops Attention (MoLA) uses keys and values (KV) as memory for selective reuse across depths and loops. Under loop residual, MoLT-R retains the residual stream and reads local KV across loops for expressivity. Under loop KV, MoLT-KV instead restarts from embeddings and reads current-loop local KV with preceding-loop memory KV at earlier positions for efficiency. MoLT-KV eliminates same-position cross-loop dependence and, paired with loop forcing for parallel training, unlocks single-traversal Mixture-of-Loops (MoL) decoding beyond the training loop horizon. To balance efficiency and quality, we introduce U-shaped MoLT (U-MoLT), which separates memory construction from prediction readout and skips unused decoder traversals without changing predictions. In 400B-token pretraining, U-MoLT outperforms OLMo3 across 700M/1.5B dense and 3B MoE models, achieving 1.7x validation cross-entropy (CE) token efficiency at 700M while improving 3B MoE 10-domain perplexity by 0.75 and 10-task accuracy by 2.1 percentage points. In 100B-token continued pretraining of Qwen3.5-0.8B-Base, our U-MoLT adaptation lowers CE on all 11 domains over the matched baseline with 1.4x mean token efficiency. At inference, U-MoLT with MoL-Hybrid-2 matches non-looped OLMo3 latency at 996.6 vs. 1,000.6 ms on S-size (~113M) models. Code is available at https://github.com/hustvl/MoLT
