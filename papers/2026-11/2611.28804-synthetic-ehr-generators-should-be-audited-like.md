# Synthetic EHR Generators Should Be Audited Like LLMs

> **arXiv**：[2611.28804](https://arxiv.org/abs/2611.28804) · **主题**：`效率、系统与安全` · **发表**：2026-11-21 · **Venue**：NeurIPS 2026
> **作者**：Inigo Stibbe、Padmanabhan Ramnarayan、A. Aldo Faisal · [PDF](https://arxiv.org/pdf/2611.28804) · [HTML](https://arxiv.org/html/2611.28804)  
> 状态：每日精读（智能体）

## 一句话结论
把 1,000 个 MIMIC-IV 患者轨迹故意过拟合到 49.5M 参数的 GPT-2 式模型上，随机分配的 per-patient canary（A/B 标签）在训练患者上被系统性复现（μ̄=0.969，τ0.95=+0.925），而留出 28,560 人上 μ̄=−0.002、τ0.95=−0.001，正好落在随机零假设；同时轨迹重建在训练患者上随上下文长度接近满分。

## 为什么值得读（观点）
这是立场文，但做了一件少见的事：给“合成 EHR 的隐私评测”造正对照。四家有成员推断（MIA）结果的生成器——PromptEHR、HALO、CEHR-GPT、RawMed——对“成员推断”的定义、病人表示（visit 多热 vs 事件 token 序列）、攻击信号（shadow model / likelihood / Hamming 距离）、判决规则全不一样，所以聚合 AUROC 接近 0.5 的结论其实什么都没证明。

## 问题与动机
合成 EHR 越来越多用自回归大模型，等价于 LLM 的逐 token 条件预测，于是继承了 LLM 式记忆风险：给定病人前序上下文，模型可能复现其后续记录（Carlini 的 extractable memorization 定义可直接搬过来：p 是观测到的轨迹前缀，s 是续写或敏感属性）。但现行隐私评测靠相似度启发式与数据集级聚合指标，会把“少数罕见病人被记住”的尾部风险平均掉；监管（GDPR/HIPAA）也没给出技术框架。

## 方法与关键洞察
核心设计是 canary：给每个病人随机（P=0.5）贴 A/B 标签、拼到轨迹尾部，标签与临床内容独立，因此“能预测出这个标签”只能来自病人级记忆而不能来自临床规律——这是把“重建正确”与“背下这个人”分开的关键。定义 π_i 为真实 canary 的成对概率、μ_i = 2π_i−1，零假设下 μ 关于 0 对称，用超尾统计量 τ(γ) 检验正负不对称。数据侧用 ETHOS 转 MEDS 格式，49.5M GPT-2 式模型，只喂 1,000 个病人并训到极端过拟合，构造“应该能测出记忆”的正对照。

## 证据与实验
记忆分数：训练集 n=1,000，μ̄=0.969、τ0.95=+0.925；留出 n=28,560，μ̄=−0.002、τ0.95=−0.001（分布关于 0 对称，模型常很自信但方向随机）。固定目标重建（greedy 解码，预测第 401–500 个 token，取 ≥500 token 的轨迹，n=406 训练 / 1,000 留出）：训练患者随上下文增长接近完美，留出患者明显更低且随上下文只微升。作者明确说明这是 positive control，不是对真实训练规模下记忆率的估计。

## 可质疑之处
①训练只有 1,000 人并刻意过拟合，canary 分数饱和到 0.969，恰恰使“canary 分数 ↔ 重建准确率”的关系无法估计（作者自己承认），所以本文只证明“能测到”，没证明“阈值该定在哪”。②canary 是拼在轨迹尾部的两 token 二分类，模型完全可以只记住“此人配 A”而不记住任何临床事件——它证明的是病人级关联被记住，不是 PII 可提取，作者也承认。③τ 的零分布与显著性流程没有给出可操作版本（如何定 γ、如何做多重比较），难以直接落地成发布门槛。④单数据集（MIMIC-IV）、单模型族（GPT-2 式 49.5M），对现在上亿参数的 EHR 基础模型外推性未知。⑤没有把 MIA/NNAA 在同一模型上做对照，“聚合指标掩盖尾部风险”这个核心论断目前是论证而非实证。

## 与我的研究关联
做病理语音/医疗多模态时会用到合成数据（合成语音、合成病历），这套方法论可直接平移：给每条合成样本注入与内容无关的随机 canary，检查生成模型是否“记住”了它——这是判断“只学到分布”还是“背下了个体”的低成本正对照。对做去标识化/差分隐私评测的人也直接可用；注意它的正对照设定意味着结论只能当“检测器有效”，不能当“泄漏率估计”。

## 摘要原文

<details>
<summary>展开英文摘要</summary>

Synthetic electronic health record (EHR) generation is increasingly adopting large autoregressive models, yet privacy evaluation has not kept pace, relying heavily on similarity-based heuristics and aggregate metrics that can obscure patient-specific memorisation. We argue that these models should additionally undergo LLM-style memorisation audits at the level of individual patient records. We support this position by comparing membership-inference evaluations across four prominent autoregressive EHR generators, highlighting inconsistent evaluation practices in patient representations and attack procedures. We evaluate trajectory reconstruction from partial context and introduce randomly assigned patient-level canaries to distinguish memorised associations from clinical generalisation. We examine these methods in a GPT-2-style model deliberately overfit to 1,000 MIMIC-IV patient trajectories, creating a controlled setting in which memorisation should be readily detectable. The model systematically recovers training patients' canaries, and their trajectory reconstruction approaches perfect accuracy with increasing context. Held-out patients show no systematic canary recovery, while reconstruction remains low and improves only marginally with additional context. These experiments establish a positive-control baseline for further evaluation of these methods in realistically trained models.
