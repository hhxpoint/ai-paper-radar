# OS-Omni: Benchmarking Generalist Computer-Using Agents on Long-Horizon Workflows Across Platforms

> **arXiv**：[2611.34232](https://arxiv.org/abs/2611.34232) · **主题**：`大模型与推理` · **发表**：2026-11-25 · **Venue**：NeurIPS 2026

## 一句话结论
把 OSWorld 式的桌面评测扩成跨平台 + 长程 + 终态判分：300 条任务 = 六平台各 48 条 + 12 条跨设备工作流，人类平均要 67.54 步 / 200.97 秒（OSWorld 参考 15.0 步 / 111.94 秒）；v1 上最强的 Claude Opus 5.5 平均 68.5%，比人类 77.3% 低 8.8 点，且平台间极不均匀——三个前沿模型在 Linux 上全部超过人类 74.6%，而 iOS 最好只有 41.7%（低 33.5 点）、macOS 54.2%（低 25.6 点）。

## 为什么值得读（观点）
值得读的是它的评测量尺，而不是又一个榜单：① 判分只认持久化的终态（解析办公文档、查应用数据库、看外部存储），不认「看起来做完了」，这把「视觉上合理的轨迹」和「真的完成了」分开；② 60% 的任务（180/300）跑在自建的 18 个 Open 系列 mock 应用上（OpenShop、OpenBank、OpenTrip 等），换取可复现初始化与可靠终态校验，代价是保真度；③ 12 条跨设备工作流把 Android 手机投到桌面 scrcpy 窗口里，agent 要在单屏上跨设备搬文件、回传结果——这一类最能区分头部模型（Claude 83.3% 追平人类，GPT-6 58.3%、Gemini 50.0%）。反常识的观察是：差距的来源主要不是「看不懂界面」，而是状态跟踪与持久化——错误分类里视觉 grounding、状态跟踪、持久化、平台与时序四类并列。

## 问题与动机
现有 GUI 基准各守一处：浏览器（WebArena/Mind2Web）、移动（AndroidWorld）、桌面（OSWorld/WindowsAgentArena），动作空间、任务风格、打分协议都不同，于是「在某一族环境上很强」无法当成通用计算机使用能力的证据。真实用户目标是跨软件的：比价、加购物车、改预算表、建日历、导出文件、发消息，每一步都不难，合起来跨约定、跨应用、且必须以终态正确为准。作者主张评测要同时覆盖广度（平台）与深度（工作流）。

## 方法与关键洞察
任务规范 = 自然语言指令 + 可复现初始化 + 平台适配器 + 可执行终态评估器，成功由 R(τ)=g(s_T) 决定，与参考轨迹无关。环境层：统一编排层加平台适配器，重置分别用 Linux 快照、Windows 金镜像、macOS Tart 克隆、iOS 模拟器克隆、Android ADB 重置。动作空间两层：PyAutoGUI 风格的通用语义层负责可写，原生后端层（桌面事件、ADB tap、Appium/XCUITest）负责可执行。观测以纯截图为默认（跨平台最均匀），也支持无障碍树与组合模式。关键洞察是「重置与终态评估是环境契约的一部分」——GUI agent 会改文件、账号、缓存，不先把基线恢复，任务不可复现。

## 证据与实验
v1：300 条（六平台各 48，跨设备 12），四大类为日常 138（46.0%）、专业生产力 59（19.7%）、跨应用 53（17.7%）、Web 50（16.7%），34 个二级类；30 名计算机研究生用两个月、约 2,400 人时标注加 400 人时复核，五阶段流程含 oracle 轨迹验证与失败态测试。九个模型：人类 77.3 宏平均（各平台 72.6–83.3），Claude Opus 5.5 68.5、GPT-6-Astra 66.1（微平均 67.0，201/300）、Gemini 4 Argon 58.6；DeepSeek V4.1 Flash 30.4、GLM-5.3-753B 23.5、Kimi K3 22.0、Qwen 3.8 Max 13.1、Qwen 3.8 27B 1.2、9B 0.0。平台极端值：Gemini 在 Linux 95.8（人类 74.6），Claude 在 Linux 85.4 但 iOS 41.7；GPT-6 在 Windows 66.7 / macOS 50.0。跨设备：Claude 83.3 追平人类，GPT-6 58.3、Gemini 50.0，Qwen 27B/9B 全零。

## 可质疑之处
① 每平台 48 条 ⇒ 单条任务在该平台等于 2.08 点，主表没给置信区间；像 macOS 50.0 vs 54.2 这种差距只相当于 2 条任务，跨设备组 12 条更是每条 8.3 点（作者自己提示要谨慎读）。② 人类参考只写了「有基本软件使用技能、此前未接触任务」的标注者，没说每人每任务跑几条轨迹、是否取最好一次；若人类只跑一次而模型跑多次或反之，77.3% 与 68.5% 的可比性存疑。③ 60% 任务依赖自建 mock 应用：mock 的交互复杂度、错误提示、加载延迟都低于真实站点，而 Linux 与 Web 又恰好是 mock 与浏览器最成熟的两块，这正好对上「Linux 上三个前沿模型超过人类」的异常。④ 主实验是纯截图 + 最近三步历史；无障碍树模式虽支持但未评估，所以「agent 缺平台鲁棒性」这个结论混合了观测模态的局限，不能完全归因于模型能力。⑤ 评估器可被绕过：agent 有终端动作，理论上可直接改应用数据库或写目标文件而不走 GUI；论文只提 oracle 变体用于调试，没有针对「绕界面直接改状态」的对抗分析。⑥ 以 300 条为一波滚动发布，v1 任务在模型训练截止之后仍可能泄入后续训练数据，未来版本的分数需要按发布时间对齐才有意义。

## 与我的研究关联
四类失败模式（视觉 grounding、状态跟踪、持久化、平台与时序）可以直接当 checklist 用来审自己的 agent 实验：多数「agent 看起来完成了」的失败都落在后两类，而它们恰好是只看中间截图或只看 LLM-as-judge 打分的评测最容易漏掉的。评测方法上，「终态可执行校验 + 可复现初始化 + 单屏跨设备」这套组合，可以照搬到语音 agent 或具身多模态的实验设计里——把「任务是否完成」交给可执行检查而不是人看轨迹。另一条经验是：如果 agent 有终端或直写文件的能力，评测必须防「绕过交互直接改状态」，否则分数虚高。

## 摘要原文

<details>
<summary>展开英文摘要</summary>

Computer-using agents are increasingly expected to complete realistic user goals rather than isolated GUI actions. However, existing benchmarks typically isolate web, mobile, or desktop environments, leaving it unclear whether a single generalist agent can execute long-horizon workflows that span multiple operating systems and persistent application states. We introduce OS-Omni, a live cross-platform benchmark and execution environment for evaluating computer-using agents across Windows, Ubuntu, macOS, iOS, Android, and Web environments. OS-Omni is released in versioned waves of 300 tasks each; this paper focuses on the first release, v1, which contains 48 tasks per platform and 12 cross-platform workflows that pair a desktop with an Android phone. OS-Omni provides reproducible initialization, platform-specific adapters, trajectory logging, and executable final-state evaluators, and includes controlled service-backed applications for workflows involving account, cart, budget, calendar, message, and other persistent state. Human studies show that OS-Omni tasks require 67.54 interaction steps, substantially exceeding OSWorld references of 15.0 steps. On v1, the strongest evaluated agent, Claude Opus 5.5, reaches 68.5% average success, trailing the 77.3% human reference by 8.8 points; the gap is uneven across platforms, with frontier models exceeding humans on Linux but trailing them by more than 25 points on iOS and macOS. These results indicate that current agents remain far from platform-robust, long-horizon computer use, especially when success requires sustained state tracking and durable final-state changes.
