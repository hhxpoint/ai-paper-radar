# Post-Training Agents for Long-Document Reasoning

> **arXiv**：[2611.30090](https://arxiv.org/abs/2611.30090) · **主题**：`大模型与推理` · **发表**：2026-11-23 · **Venue**：NeurIPS 2026 Workshop (LCFM)
> **作者**：Sushant Mehta、Logan Ritchie、Edwin Chen · [PDF](https://arxiv.org/pdf/2611.30090) · [HTML](https://arxiv.org/html/2611.30090)  
> 状态：每日精读（智能体）

## 一句话结论
在 Kimi-K2.7 的完整 262K 窗口上，用 1,465 条专家 rubric 任务做一轮特权上下文自蒸馏 + 两轮 rubric-RL，GDP.pdf 100 题 strict pass 从 11.0% 升到 24.5%（四次评测 23–27%），生成 token 几乎不变（9,803→9,733），即每 10 万 token 的 strict pass 从 1.12 翻到 2.52。

## 为什么值得读（观点）
反常识之处在于它不卖“更长上下文能力”，而是把长文档失败重新定义成“守不住 scope”：证据跨页、跨模态、多跳。于是被改的是 agent 的检索顺序与自检行为，而不是窗口大小；它还主张长上下文评测必须把准确率与 token、轮数一起报。

## 问题与动机
主流长上下文评测是“找针”（Hsieh、Kuratov 等），但专业文档里答案的支撑可能是一张表格三页之后才出现的脚注、要按序列号先选对图纸再跨页追线、或先确定适用哪一版合同。10 域企业集合 2,485 个任务共 121,158 页，中位 27 页、均值 48.8、最长 873 页（建筑）；70.9% 需 ≥2 跳、12.4% 需 ≥10 跳；34.5% 主要依赖图表/图纸/地图，另有 15.1% 图文各半。前沿仍未解：集合上最好 pass@1 仅 38.5%（GPT-5.6 Sol Medium），GDP.pdf 榜首 strict pass 30.7%。任务要求模型在一次回答里同时守住范围、排除项、视觉编码与定义。

## 方法与关键洞察
渲染是前置条件：训练把 PDF 转成 Markdown（表格/图表由 GPT-5.4 Mini 转写，地图与平面图转结构化记录），否则 1,465 条任务里多数会超过 256K 上下文；评测则用全文抽取 + 至多 16 张页面图，页面图占输入 token 的大头。第一轮是特权上下文同策略自蒸馏：学生先采样回答，同一 checkpoint 带着“针对 rubric 的批评 z”当老师，对同一批已采样 token 做 token 级 KL（无任务奖励）；后两轮用 rubric 奖励做 GRPO——奖励是严重度加权的通过率（primary-intent 按 1.0/0.6/0.3，dodged-bullet 记为惩罚、结果下限为 0），每 prompt 采 8 条，6.5 万 token 上限，rank-32 LoRA，64 张 H200。关键工程细节是给学生的 max_new_tokens 预先扣掉老师提示长度，避免老师提示把学生回答截断后仍被当成完整答案训练。

## 证据与实验
域内 strict pass：11.0% → 13.0%（R1）→ 24.5%（R2），criterion pass 0.660→0.765；token 9,803→10,775→9,733。四个长度桶全部上涨，尤其 >128K 桶 10.5%→30.3%，长输入涨幅 − 短输入涨幅 = −1.1 点（95% bootstrap [−13.0,+9.7]），没有证据表明增益随输入变长而衰减。域外 220 个 GDPval 任务（长程 agent + 工具 + 交付物）：mean rubric reward 0.571→0.746，零分任务 54→10，消息数 70.9→58.2（−18%）。配套报告的会话统计：命名源文件覆盖 76.1%→89.9%、只读调用/写调用 2.77→1.72、检索文本 13,459→7,172 token、唯一占比 67.0%→73.9%、可执行自检比例 5.3%→14.9%。但前沿参照用 3,422 token 就拿到 30.7%，效率差距几乎没动。

## 可质疑之处
①效率对比不干净：GPT-5.6 Sol 的 strict pass 取自公开榜单（另一套 harness），token 数是作者自测，两者相除得到的“每 10 万 token 通过数”是跨源拼接，作者自己承认，因此“准确率差距缩小、开销差距没缩小”只是方向性结论。②训练渲染（Markdown 转写）与评测渲染（抽取文本 + 页面图）不同，没有做渲染消融，+13.5 点里有多少来自评测时额外给了 16 张图无法分离。③rubric 由 GPT-5.4 Mini 判分且带严重度权重，没有 reward hacking 审计（例如模型学会迎合判分器的措辞）。④100 题 holdout 四次 run 就从 23% 波动到 27%，24.5% 与 30.7% 的差距在噪声量级附近，却用 McNemar 与四次均值包装成稳健增益。⑤M3 在顶部反而退步（满分 13→9），且作者因约 40% 轨迹只发一条 reasoning 就结束而弃用 3 次 GDPval 评测中的 2 次，存在选择性报告。⑥M1 域外已到 0.742 而域内只到 13.0%，两轮 RL 的 +11.5 究竟来自 rubric 信号还是单纯多训，缺少等算力的继续预训练/SFT 对照。

## 与我的研究关联
智能体与 RL 方向可直接搬两件事：一是严重度加权 rubric 奖励（把“漏掉排除项”记成惩罚而不是不给分），二是“准确率—token—轮数”三维汇报，避免用变长的推理堆分数。语音侧的 agent（边说边查的 ASR/TTS 前端、长录音问答）同样会遇到 context thrashing，它的 paired-trajectory 分析法（同一任务跨 checkpoint 对比同一会话）比平均分更能说明机制。多模态读者要注意“评测时页面图占输入 token 大头”这一条，它直接影响任何按 token 计成本的部署估算。

Professional documents are a long-context workload that retrieval-style benchmarks do not capture. In a ten-domain enterprise collection, a task's evidence is spread across a source document of median length 27 pages (mean 48.8, maximum 873); a third of tasks rest mainly on charts, drawings, and maps; and 70.9% require two or more reasoning hops. We post-train Kimi-K2.7, an open-weight foundation model, at its full context window on 1,465 expert-authored tasks with atomic rubrics from that collection, training rank-32 adapters with one round of privileged-context on-policy self-distillation followed by two rounds of rubric-reward reinforcement learning. We render each PDF as text for training and as extracted text plus selected page images at evaluation. The smoothed RL training reward rises from 0.37 in the first tenth of the run to 0.67 in the last. On the 100-task GDP.pdf holdout, served in a 262,144-token window, strict pass (all rubric criteria met) more than doubles after the second round, from 11.0% to 24.5%, with gains across input lengths up to 240K tokens. Mean tokens generated stay flat (9,803 to 9,733), so the gain does not come from longer outputs. GPT-5.6 Sol's leaderboard strict pass is 30.7% at a measured 3,422 tokens. On 220 out-of-domain GDPval tasks, where the model runs as a long-horizon tool-using agent, mean rubric reward rises from 0.571 to 0.746 after the third round and zero-credit tasks fall from 54 to 10, while messages per task fall 18%, from 70.9 to 58.2. In paired trajectories, the third round replaces a context-thrashing retry loop with one up-front check of all sources, and verification extends from checking that files exist to checking what they contain. We argue that long-context evaluation of agents should report accuracy jointly with tokens and turns, and that datasets of long documents should ship text and image renderings alongside each PDF.
